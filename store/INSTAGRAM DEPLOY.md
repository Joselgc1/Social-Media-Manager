# Native Meta Instagram Deployment

## Architecture

Instagram is always native Meta and is never connected to Kommo:

```text
Instagram DM, Story interaction, or public comment
  -> GET/POST /webhooks/instagram
  -> signature verification and normalization
  -> durable meta_inbound_jobs + meta_inbound_receipts
  -> AI engine for private messages, deterministic handler for comments
  -> Meta Graph API reply
```

WhatsApp may independently use Meta or Kommo through `WHATSAPP_BACKEND`; that setting does not change Instagram routing. Do not create an Instagram Kommo Salesbot, subscribe Kommo to Instagram, configure an Instagram backend selector, or use the retired context-only `/webhooks/meta/instagram-context` route.

Migration `018_retire_kommo_instagram.sql` deprecates live legacy Instagram/Kommo processing but intentionally does not drop the old correlation schema. Historical correlation rows and columns may remain in upgraded databases and must not be treated as active architecture. Before deploying it, disable legacy Instagram Kommo ingress and wait for active jobs to drain; the migration fails closed rather than abandoning a launched Salesbot or uncertain delivery.

## Prerequisites

- Meta Business app associated with the correct Business Portfolio.
- Instagram Professional account (Business or Creator) linked to a Facebook Page.
- Facebook administrator with access to the Page and Instagram account.
- Required business verification, App Review, and Advanced Access shown by the current Meta dashboard.
- Public HTTPS store URL and a single Store application instance.

Use the Graph API version currently supported and tested for the app. Meta's dashboard is authoritative for current permission names, review requirements, and webhook subscription fields.

## Credentials

Configure the native Instagram values expected by the Store:

```env
META_APP_SECRET=
INSTAGRAM_ACCESS_TOKEN=
INSTAGRAM_VERIFY_TOKEN=
INSTAGRAM_ACCOUNT_ID=
META_GRAPH_API_VERSION=vXX.X
APP_BASE_URL=https://YOUR-STORE-DOMAIN
```

- `META_APP_SECRET` validates `X-Hub-Signature-256` on the raw webhook body.
- `INSTAGRAM_ACCESS_TOKEN` is the durable token used for Instagram Graph API reads and sends.
- `INSTAGRAM_VERIFY_TOKEN` is a random value generated by the operator for callback verification.
- `INSTAGRAM_ACCOUNT_ID` identifies the managed Instagram Professional account.

Generate a verify token with:

```bash
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

Never commit or log access tokens or the app secret. Monitor token validity and expiration; the application does not renew Meta tokens automatically.

## Meta App Setup

1. Link the Instagram Professional account to the correct Facebook Page.
2. Associate the Page, Instagram account, app, and administrator with the same Business Portfolio.
3. Add the Instagram messaging/Graph API and Webhooks products required by the current Meta setup flow.
4. Complete the app's contact email, privacy policy, data deletion, category, and icon fields.
5. Request the permissions and access levels Meta currently requires for DMs, message management, comments, Page metadata, and media reads used by this deployment.
6. Obtain and test the durable production token and Instagram account ID.

Before webhook setup, verify the token can read the managed account and recent media through the selected Graph API version. If account discovery returns no Page or Instagram account, check the selected app, granted permissions, Page access, Business Portfolio ownership, and Page/Instagram link before regenerating the token.

## Deploy And Migrate

Deploy the Store with root directory `store/` and one replica. Railway pre-deploy runs:

```bash
python scripts/migrate.py
```

The current Store schema version is `18`. Back up an existing production database before migration. Use `002_consolidated_upgrade.sql` only for a documented pre-consolidation recovery, then rerun the normal migration runner.

Set `APP_BASE_URL` to the final public domain and deploy the Meta credentials. Confirm `/health` is healthy before connecting webhooks.

## Webhook Subscription

In the Meta App Dashboard, configure the Instagram webhook object:

```text
Callback URL: https://YOUR-STORE-DOMAIN/webhooks/instagram
Verify token:  exact INSTAGRAM_VERIFY_TOKEN value
```

Subscribe to the Instagram fields required for the enabled behavior, including private messages and public comments. Include Story/message fields only when the current Meta product and permissions support those events. Then subscribe the managed Page/account to the app using the current Meta-supported flow.

The same endpoint handles verification and delivery:

- `GET /webhooks/instagram` returns Meta's challenge after verify-token validation.
- `POST /webhooks/instagram` rejects invalid signatures and durably commits accepted events before acknowledgment.

Do not point Meta at `/webhooks/meta/instagram-context`; that retired route belonged to the old Kommo correlation design.

## Page Subscription And Ice Breakers

After credentials and App Review are ready, use the authenticated Store helpers where applicable:

```bash
curl -X POST "https://YOUR-STORE-DOMAIN/admin/settings/instagram/subscribe-page?page_id=YOUR_PAGE_ID" \
  -H "Authorization: Bearer YOUR_ADMIN_PASSWORD"

curl -X POST "https://YOUR-STORE-DOMAIN/admin/settings/instagram/setup-ice-breakers?ig_user_id=YOUR_IG_USER_ID" \
  -H "Authorization: Bearer YOUR_ADMIN_PASSWORD"
```

Set the Meta app to Live only after all access and review requirements are complete.

## Content Mappings And Comments

Open `/admin/login`, then use the Instagram dashboard tab to map posts, Reels, carousels, and discovered Stories to catalog products. Start with one active post mapped to one known product.

Public comment processing is deterministic and uses the native Meta comment ID for idempotency:

- A mapped single product can answer price or availability directly.
- Multiple mapped products require clarification unless the comment confidently identifies one product.
- Other questions use the DM/WhatsApp fallback controlled by `store_phone_number`.
- Replies are posted through Graph `/{comment_id}/replies`.

No Kommo job, callback, mirror, or correlation event participates in this flow.

## Private Messaging Behavior

- DMs, quick replies, ice breakers, postbacks, shares, Story interactions, images, and supported audio metadata enter `meta_inbound_jobs`.
- Rapid messages are durably debounced into one AI turn per customer/channel.
- Native Instagram audio attachments are transcribed with OpenAI before AI execution; this requires `OPENAI_API_KEY` even if Anthropic is the chat provider.
- Accepted outbound Meta message IDs identify application echoes. Unknown outgoing echoes are treated as manual administrator replies and place the customer in indefinite manual escalation.
- Resume AI preserves Instagram conversation history while resetting workflow/session state.
- Instagram remains informational; checkout, payment, and catalog PDF requests hand off to WhatsApp.

## Staging Tests

Use a separate Railway environment and database when validating a new Meta app or token. While the app is in Development mode, real test users generally need an app role allowed by Meta.

```text
[ ] Migration runner accepts schema version 18
[ ] GET /webhooks/instagram verifies with the configured token
[ ] Unsigned or incorrectly signed POST returns 403
[ ] Real DM creates one meta_inbound_jobs row and one Meta reply
[ ] Rapid DMs debounce without duplicate replies
[ ] Ice breaker and quick reply callbacks work
[ ] Story reply reaches the native Meta queue when subscribed
[ ] Real mapped comment creates an instagram_comment Meta job
[ ] Price/availability comment receives a Graph API public reply
[ ] Unmapped or unsupported comment uses the safe fallback
[ ] Manual outgoing Instagram reply pauses AI for that customer
[ ] Instagram traffic creates no kommo_message_jobs rows
```

Meta's synthetic Test button proves callback reachability, not complete production behavior. Always test a real DM and real comment from an allowed external account.

## Production Cutover

1. Back up StorePostgres.
2. Deploy the application revision and migration 018.
3. Deploy production Meta credentials and final `APP_BASE_URL`.
4. Verify `/health`, admin login, catalog loading, and content mappings.
5. Verify and save `https://YOUR-STORE-DOMAIN/webhooks/instagram` in Meta.
6. Confirm all required fields remain subscribed and the app is Live.
7. Send one controlled DM and one mapped comment.
8. Inspect `meta_inbound_jobs`, `meta_inbound_receipts`, conversations, and Graph API delivery logs.
9. Confirm no Instagram event enters Kommo.

## Troubleshooting

- Callback verification fails: check the exact verify token, public HTTPS URL, and deployed environment.
- POST returns 403: verify `META_APP_SECRET` belongs to the app sending the webhook and no proxy modifies the raw body.
- DMs/comments do not arrive: confirm Professional account status, Page link, app Live mode, account subscription, webhook fields, token validity, and required access level.
- Account/media query fails: confirm the token type, Instagram account ID, Graph API version, permissions, and asset ownership.
- Mapping is not found: confirm the mapping is active, URL/media ID resolves to the same content, and mapped SKUs exist in the current catalog.
- Duplicate or missing replies: inspect durable Meta job/receipt status and accepted outbound message IDs before manual retry.
